# Project instructions

Whenever a user request establishes or changes a rule for the entire design system, record it in `docs/design-system-rules.md` and implement it using shared tokens or reusable graph-derived logic. Do not hardcode node-specific or screenshot-specific exceptions. Read that file before changing shared diagram behavior.

The main application now contains navigation, task conversations and an on-demand reading window, confirmed 2026-09-25. The existing Iteration Gallery and Version stream remain together inside the reading window and at `?view=history`. Preserve their behavior. Builder means creator; Inbox currently contains Mits only; human collaboration is out of scope; Input / Output cards stay at the conversation’s upper right. Use the user-supplied MitWerk design-system palette with the existing reading-window typography and density; see `docs/design-system-rules.md`.

The local app always runs on port **5173** (`http://localhost:5173`). Do not change this port, pick a fallback port, or point screenshots, OAuth redirects, or other local URLs at a different one.

Version stream progress captures default to Commit history. Use `--tree-mode test` only when a debug/Test visual capture is explicitly requested.

`c theater w/ ...` means capture the theater screen with the states that follow. For example, `c theater w/ playhead at last frame` captures theater with the playhead on the last frame in the current date range. `c gallery w/ ...` means capture the isometric gallery with the states that follow. `c gallery w/ reset view` opens Reset view. `c token` captures the cumulative token-usage view. `w/ tip hovered` leaves the gallery info tip open. `c chat "Title"` captures that conversation with the reading window closed. `c chat` without a title captures the open conversation the same way. `w/ page scrolled to top` leaves that conversation at the top of its messages. `c chat and version side by side` captures that conversation with the version-control reader open beside it, not expanded. `w/ toast triggered` keeps the unavailable-action toast on screen. `c to-dos` (or `c todos`) captures the Todos board with the reading window closed.

Progress captures include the full prototype interface (navigation and reading window), never only the isolated version panels. `c home` captures the default launch: Implementing 3D version blocks with Chat and Version control side by side. Each chat includes Chat and Version control tabs and opens side by side by default; fullscreen expands the selected pane. Explicit `c chat` captures still close the reading window.

Progress captures follow the gallery view the prompt is changing. A prompt about theater opens theater and waits for that frame. A prompt that starts with `c theater` is a theater capture. A prompt about the isometric album (isometric, overhead, reset, or top view) captures that album view. When a prompt names both, theater wins only if it does not ask for the isometric view instead.

On git push, snapshot the pushed tree into `[ver capture] codebase/` as a folder named like the matching push screenshot. Start numbering at push #6; do not commit that folder.

Do not take a progress screenshot or increment the prompt counter for Ask mode prompts. `x counter` means the same exclusion for the current prompt: do not take its progress screenshot and do not increment the prompt counter. Do not include progress-capture images in chat output.

When the git branch is not `main`, include that branch name in prompt/push screenshot names and version-archive folder names.

When the user appends screenshots, save them in the existing `visual_ref/` folder. Do not create a separate visual-ref folder. Change the start of each filename to `[prompt #x]`, using the prompt number for that request, and keep the rest of the original filename.

Progress counters (source of truth for agents working across chats): **push #25 · prompt #266**. Read this file at the start of every prompt to get the latest counters; never rely on conversation memory. In Cursor, the stop hook saves exactly one progress capture per Agent-mode prompt, from the user prompt, so a cued location (`c theater`, `c gallery`, `c chat`, `c home`, `c token`) is the frame that is saved. In Codex sessions without that Cursor stop hook, save exactly one capture before finishing with `node scripts/screenshot-progress.mjs --tag prompt --manual-prompt --label "<user prompt>"` and the requested view option. For an explicitly requested missing capture, this command is also the recovery path; use the previous prompt as the label and the requested capture view. Check the capture folder first and never duplicate an existing capture. The script updates this counter only after successfully saving the image. Do not increment the counter yourself. After a real git push, set the push number to the new `[push #N]`. Ask mode and `x counter` skip the capture and leave the counter unchanged. A requested catch-up capture belongs to the previous prompt and does not count the current request separately; reuse that previous prompt's reserved number if it has no frame, otherwise use the next available number without overwriting an existing capture.

End every user-facing response with one line naming the current push number and the latest progress-screenshot prompt number, in the form `push #5 · prompt #25`. Use the counters in this file. If they look stale, reread `[frame capture] screenshots/` and update this file first. Do not print a version label here. Do not omit this footer.
